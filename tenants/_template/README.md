# Tenant template

`training-profile.json` is the portable input for the autonomous curriculum
pipeline. Keep it factual and tenant-specific; see `docs/TRAINING_AUTOMATION.md`.

Copy this folder to `tenants/<slug>/` to onboard a brand. The full file list:

- `brand.json` — customer and kiosk identities, palette, type pairing, feature flags, fees, and the
  copy dictionary (documented field-by-field in the file's own `$docs` block)
- `menu.csv` — the menu the onboarding script seeds; the example rows exercise
  every feature (multi-size, single-serve, quoted commas)
- `menu-categories.json` — stable category ids, display titles, and the short
  taglines shown above each menu section; titles must match `menu.csv`
- `modifiers.json` — option groups per item slug, in the engine's
  menu-pricing shape; optional per item, and every key must exist in menu.csv
- `assets/` — the brand's own artwork:
  - `logo.svg` (preferred) or `logo.png` — the master onboarding generates
    icons and splash art from
  - `hero/` — home hero video and stills
  - `gift/` — gift-card artwork
  - `rewards/` — rewards illustrations
  - `menu/` — item photographs, `<item-slug>.webp`, square 900×900 WebP
  - `products/` — alpha product cut-outs for the shelf

  Each subfolder has its own README with naming and format rules.
- `app-store/` — generated output only (listing draft, screenshots checklist,
  icon art); regenerated by onboarding, never edited by hand

`pnpm onboard --tenant <slug>` validates and generates tenant output.
`pnpm onboard --tenant <slug> --apply` also refreshes the customer and kiosk
bundles, including their native identity, icons, splash art, and media. See the
root `CLAUDE.md` ("How to onboard a tenant").
